# 대화형 Card 관리 — 기획 중

기준일: 2026-10-12. grill-with-docs에 따라 확인된 요구사항과 제안을 분리한다.
대화형 Card 관리의 전체 기능 명세는 기획 중이다. 2026-10-12 사용자가 앱 내부 에이전트 토글과 자연어 작업 UI 구현을 요청했다. 사용자 개인 Card 내용은 기록하지 않는다.

## 사용자 확인 사항

- 목적: 새로 생긴 일을 Card로 등록하고 기존 Card의 내용을 수정하거나 완료 처리하는 수고를 줄인다.
- 사용자는 자연어로 대화하고, 에이전트는 적절한 등록·수정·완료 변경안을 준비한다.
- 변경은 사용자가 `DONE` 버튼을 눌렀을 때만 실제 Card에 반영한다.
- 초기 참고 범위는 앱 안의 Card·메모·체크리스트 및 사용자가 직접 붙여넣은 자료다.
- 첫 진입점은 TO-DO ZONE 내부 에이전트 토글과 대화 UI다. DOT은 후속 부가기능이다.

기존 D-009의 AI 채팅 제외는 최초 MVP 범위다. 이 문서는 그 이후 확장 기획이며,
최초 MVP 문서나 구현 상태를 소급해서 바꾸지 않는다.

## 제안하는 사용자 흐름

1. 자연어 요청을 받는다. 하나의 요청에 등록·수정·완료가 함께 있을 수 있다.
2. 실제 Card를 조회하고 변경 대상과 신규 등록 여부를 식별한다.
3. 여러 Card가 일치하거나 날짜가 모호하면 후보를 보여주고 질문한다.
4. 신규 Card는 예정 필드, 기존 Card는 변경 전후를 보여준다.
5. 사용자는 대화로 변경안을 고치고, 적용할 항목을 선택한다.
6. 사용자가 `DONE`을 누르면 선택한 변경을 검증하고 반영한다.
7. 실제 반영 결과와 해당 Card를 보여준다. 저장 실패를 완료로 알리지 않는다.

`DONE` 버튼은 변경 적용 행위이고, 기존 용어 `Done`은 Card의 Status다.
두 의미를 혼동하지 않도록 버튼 보조 문구를 `변경 적용`으로 표시하는 안을 제안한다.
등록·Due date 변경만 선택된 경우 버튼을 눌러도 Status가 Done으로 바뀌지 않는다.

## 구현 요구 후보 — 아직 미확정

- 에이전트는 Card 조회와 변경안 준비를 수행하고, 실제 쓰기 권한은 사용자 승인 경로에서 검증한다.
- 승인 대상에는 검토한 변경안의 버전을 연결한다. 승인 후 내용이 바뀌면 다시 검토한다.
- 적용 직전 대상 Card가 수정되었으면 덮어쓰지 않고 최신 내용과 충돌을 보여준다.
- 중복 클릭이나 재시도로 Card가 중복 생성되지 않도록 한다.
- 선택한 변경 묶음은 전부 적용하거나 실패 시 기존 상태를 유지하는 방식을 제안한다.
- 명확하지 않은 Project는 Inbox를 제안하며, Due date는 임의로 만들지 않는다.
- 상대 날짜는 사용자 시간대를 기준으로 해석하고 적용 전에 실제 날짜를 표시한다.
- 삭제, Project·Area 생성/삭제, 자동 일정 감시는 초기 확인 범위에 포함하지 않는다.
- 작업 결과물 작성·우선순위 추천은 현재 핵심 요구보다 후순위 후보로 둔다.

## DOT 연동 조사와 제안

확인한 공식 문서:

- DOT은 계정에 설치·활성화되고 권한이 부여된 지원 플러그인을 사용할 수 있다.
  https://learn.chatgpt.com/docs/dots
- 직접 만든 MCP 서버를 ChatGPT 플러그인으로 연결할 수 있다.
  https://developers.openai.com/api/docs/guides/custom-mcp-server
- MCP 서버는 검토·편집·확인이 필요한 흐름에 선택적으로 UI를 제공할 수 있다.
  https://developers.openai.com/plugins/build/chatgpt-ui

위 문서에 근거한 설계 제안:

- 앱에 인증된 MCP 연결을 추가하여 DOT이 Card 조회 및 변경안 준비 기능을 사용하게 한다.
- DOT이 만든 변경안은 앱에 저장하고, 사용자는 앱의 검토 화면에서 `DONE`을 누른다.
- 앱 내부 대화 기능과 DOT 연결이 같은 Card 데이터 및 승인 절차를 사용하도록 한다.
- DOT에 실제 Card를 바로 변경하는 승인 우회 도구를 제공하지 않는다.
- 현재 앱의 브라우저 로그인만으로 MCP 인증이 완성되는 것은 아니다. 외부 연결 인증은 별도 설계한다.
- DOT 대화 안에 검토 UI를 표시하는 방법은 후속 검증 대상이다. 초기에는 앱 검토 링크를 사용할 수 있다.
- 이것은 TO-DO ZONE을 DOT이 사용하는 도구로 연결하는 구상이다. 앱 안에 사용자의 DOT이나 그 기억을 임베드할 수 있다는 의미가 아니다.
- 사용자 계정의 커스텀 플러그인 가용성과 DOT에서의 실제 호출은 아직 검증하지 않았다.

## 다음 결정

1. AI 제공자·모델 연결과 실제 변경 적용 API는 후속 구현 범위다.
2. 대상 식별이 모호한 경우: 일치 후보를 물어보고 확정한 뒤 변경안을 준비하는 것을 권장한다.
3. 위 결정 이후 대화 화면, 승인 묶음, 인증, 오류 처리의 세부 명세를 확정한다.

## 2026-10-12 UI 구현

- Board Hero의 `Agent` 토글로 열고 닫는 대화 패널. 데스크톱은 우측 패널, 모바일은 전체 화면이다.
- 자연어 입력창, 요청 시작 버튼, 변경 검토 UI, 항목 선택, 제목 수정, `DONE` 버튼을 구현했다.
- 현재 배포 환경에는 AI 모델 자격 증명이 없다. `UI PREVIEW`와 `AI 연결 전`을 표시한다.
- 자유 입력은 미실행 상태를 명확히 알린다. 임의의 규칙을 AI 해석 결과로 제시하지 않는다.
- 별도의 `변경안 예시 체험`으로 합성 Card의 등록·마감일 변경·완료 흐름을 확인한다.
- 예시 `DONE`은 체험 상태만 바꾸며 실제 Card API 호출이나 Board 변경이 없다.
- 대화와 입력은 패널을 닫아도 유지하되, 새로고침·Board 이탈·로그아웃 후에는 유지하지 않는다.
- 새 대화 시 예시 초안 삭제를 확인한다. 한글 조합 Enter 방지, 포커스 복귀와 모달 포커스 순환을 적용했다.
- 후속 연결 시 미리보기 동작을 실제 생성/검토/승인 API로 대체해야 한다. API 연결 전까지 UI 완성을 에이전트 기능 완성으로 간주하지 않는다.


## 캐릭터와 밝은 패널 (2026-10-12)

- 사용자 피드백에 따라 Agent 전용 패널을 아이보리 배경으로 바꾸고 테두리 대신 여백·파스텔 면으로 구분한다. Board 테마는 유지한다.
- 직접 생성한 세이지색 펫 PNG를 토글·헤더·대화 아바타·환영 화면에 적용한다. 실제 투명 알파를 가진 이미지는 `frontend/public/agent/zone-pet.png`에 둔다.
- 환영 화면의 작은 호흡, 입력 중 헤더의 관심 표현, 클릭 인사, 예시 DONE 후 짧은 점프를 CSS로 구현한다. PNG 한 장을 변형하는 모션이며 프레임 애니메이션은 아니다.
- 헤더에서 모션을 끄고 켤 수 있다. 운영체제의 동작 줄이기 설정을 우선한다.
- 기존 UI 미리보기의 AI 미연결 표시와 실제 Card 비변경 정책은 유지한다.

이미지 제작: 내장 이미지 생성 도구 사용. 핵심 프롬프트는 ‘투명 배경, 세이지색 말랑한 콩 형태의 작은 펫, 둥근 귀와 짧은 팔다리, 올리브색 눈과 부드러운 미소, 무광 3D 클레이, 외곽선·문구·장식 없음’이다.
